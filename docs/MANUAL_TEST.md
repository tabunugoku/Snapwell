# 実機で確かめること

自動テストはすべて偽の Win32 API で動く。ここに挙げる点は、実機で手で確かめる。確かめたら `[x]` にし、日付と環境 (x64 / ARM64、DPI、モニター構成) を書く。

OS の設定を変える項目 (「設定を変える」と書いたもの) は、ユーザーの同意を得てから行い、終わったら元に戻す。

## App: 常駐の部分 (src/Snapwell.App) — 起動するとフックを登録する

初めて起動する前に、ユーザーの許可を得る。`dotnet publish src/Snapwell.App/Snapwell.App.csproj -c Release -r win-arm64` (x64 も) で作ったものを使う。

- [ ] 起動するとトレイにアイコンが出る。二重に起動しても、2 つ目は何も変えずに終わる (実機未確認)
- [ ] エクスプローラーを再起動すると、アイコンが戻る (TaskbarCreated。実機未確認)
- [ ] トレイの「一時停止」「再開」、「標準の動作に戻す」、「終了」 (実機未確認)
- [ ] 「Windows 標準のスナップを止める」を初めて選ぶと、同意のダイアログが出る。断ると何も変わらない — 設定を変える (実機未確認)
- [ ] 止めたあと、終了・一時停止・サインアウト (セッションの終了) のどれでも「ウィンドウのスナップ」が元に戻る — 設定を変える (実機未確認)
- [ ] タスクマネージャーで強制終了してから起動し直すと、元に戻る — 設定を変える (実機未確認)
- [ ] タイトルバーをドラッグして投げると、半分・四分割・最大化・四隅に物理モデルで吸い込まれる。ゆっくり離すと通常の移動になる (実機未確認)
- [ ] 吸い込まれている途中でつかみ直すと、すぐ止まって手に戻る (実機未確認)
- [ ] DPI の違うモニターへ投げる、負の座標のモニターへ投げる (実機未確認)
- [ ] 静止したあと、CPU を使い続けない (実機未確認)
- [ ] 既定のホットキー: Ctrl+Alt+矢印 (半分)、U/I/J/K (四分割)、Enter (最大化)、Shift+矢印 (区画単位の拡大・縮小)、PageUp/PageDown (隣のモニター)、Pause (一時停止)。Ctrl+Pause が VK_CANCEL になって効かないことがないか (実機未確認)
- [ ] サイズ固定のウィンドウ、ポップアップ (タスクバーから開く小さなチャットなど) はサイズが変わらず、位置だけ動く (実機未確認)
- [ ] 「アニメーション効果」をオフにすると、すぐに配置される (実機未確認)
- [ ] 最小サイズのあるアプリを小さい区画に入れたときの位置 (実機未確認)
- [ ] 応答なしのアプリを投げた・ホットキーで動かしたときに、Snapwell が固まらず、終了できる (実機未確認)
- [ ] 設定ファイル (`%APPDATA%\Snapwell\settings.json`) を壊して起動すると、既定値で起動し、壊れたファイルが残る (実機未確認)
