OS の設定を変える項目 (「設定を変える」と書いたもの) は、ユーザーの同意を得てから行い、終わったら元に戻す。

## App: 常駐の部分 (src/Snapwell.App) — 起動するとフックを登録する

初めて起動する前に、ユーザーの許可を得る。`dotnet publish src/Snapwell.App/Snapwell.App.csproj -c Release -r win-arm64` (x64 も) で作ったものを使う。

- [x] 起動するとトレイにアイコンが出る。二重に起動しても、2 つ目は何も変えずに終わる (2026-10-17、ARM64、Windows 11 26200、5120×2160 の 1 台)
- [ ] エクスプローラーを再起動すると、アイコンが戻る (TaskbarCreated。実機未確認)
- [ ] トレイの「一時停止」「再開」、「標準の動作に戻す」、「終了」 (実機未確認)
  - 2026-10-17 ARM64: 「一時停止」「再開」「終了」は想定どおり。一時停止中は Ctrl+Alt+← がほかのアプリに届き、投げても吸い込まれない。「標準の動作に戻す」は未確認
- [x] 「Windows 標準のスナップを止める」を初めて選ぶと、同意のダイアログが出る。断ると何も変わらない — 設定を変える (2026-10-17、ARM64、Windows 11 26200、5120×2160 の 1 台)
- [ ] 止めたあと、終了・一時停止・サインアウト (セッションの終了) のどれでも「ウィンドウのスナップ」が元に戻る — 設定を変える (実機未確認)
  - 2026-10-17 ARM64: **戻らなかった**。止めると `SPI_GETWINARRANGING` は 1 → 0 になり、状態ファイルに元の値 true が残った。終了すると状態ファイルは消えたが、値は 0 のままだった。SET の値を pvParam だけに入れ、uiParam を 0 にしていたため、OS が uiParam を見てオフを書いたと見られる。uiParam と pvParam の両方に値を入れ、書いたあとに読み直すよう直した。直したもので、終了すると 1 に戻り状態ファイルが消えることを確かめた。一時停止とサインアウトは未確認
  - 止めているのはセッションの値だけで、レジストリ (`HKCU\Control Panel\Desktop\WindowArrangementActive`) は 1 のまま変わらない。戻らなかったときは、設定アプリで「ウィンドウのスナップ」をいったんオフにしてオンに戻すと直る
- [x] タスクマネージャーで強制終了してから起動し直すと、元に戻る — 設定を変える (2026-10-17、ARM64、Windows 11 26200)。強制終了のあとは 0 のままで状態ファイルが残り、起動し直すと 1 に戻って状態ファイルが消えた (止める設定をオフにして確かめた)
- [ ] 状態ファイルが残っていない通常の起動では、トレイに「復元できませんでした」が出ない。起動時の復元に失敗したとき (実機で起こすのは難しい) は、トレイに「Windows 標準のスナップを復元できませんでした。再起動時に再試行します」が出てログに残り、終了時にもう一度戻そうとする (実機未確認)
- [ ] シャットダウンを途中で取り消しても (保存していないメモ帳を残すなど)、Snapwell は常駐を続ける。本当にサインアウトしたときは、次のサインインの前に「ウィンドウのスナップ」が戻っている — 設定を変える (実機未確認)
- [ ] 標準スナップを止める処理 (SPI_SETWINARRANGING の変更の通知) が 2 秒以上固まることがないか。固まった場合は、終了しても止まったままで、次の起動で戻る (実機未確認)
- [x] タイトルバーをドラッグして投げると、半分・四分割・最大化・四隅に物理モデルで吸い込まれる。ゆっくり離すと通常の移動になる (2026-10-17、ARM64、Windows 11 26200、5120×2160 の 1 台)
- [ ] 重い処理の最中 (配送が遅れたとき) に投げても、通常の移動にならず吸い込まれる (実機未確認)
- [x] 吸い込まれている途中でつかみ直すと、すぐ止まって手に戻る (2026-10-17、ARM64、Windows 11 26200、5120×2160 の 1 台)
- [ ] DPI の違うモニターへ投げる、負の座標のモニターへ投げる (実機未確認)
- [ ] 静止したあと、CPU を使い続けない (実機未確認)
- [ ] 既定のホットキー: Ctrl+Alt+矢印 (半分)、U/I/J/K (四分割)、Enter (最大化)、Shift+矢印 (区画単位の拡大・縮小)、PageUp/PageDown (隣のモニター)、Pause (一時停止)。Ctrl+Pause が VK_CANCEL になって効かないことがないか (実機未確認)
  - 2026-10-17 ARM64: 半分、四分割、最大化、区画単位の拡大・縮小は想定どおり。隣のモニター (1 台のため) と Pause は未確認
- [x] サイズ固定のウィンドウ、ポップアップ (タスクバーから開く小さなチャットなど) はサイズが変わらず、位置だけ動く (2026-10-17、ARM64、Windows 11 26200、5120×2160 の 1 台)。確かめたのは「ファイル名を指定して実行」
- [ ] 端の余白を設定して隣のモニターへ移すと、余白の中に入り込まない (実機未確認)
- [ ] 「アニメーション効果」をオフにすると、すぐに配置される (実機未確認)
- [ ] 最小サイズのあるアプリを小さい区画に入れると、はみ出さずに作業領域の中に収まる (実機未確認)
- [ ] 応答なしのアプリを投げた・ホットキーで動かしたときに、Snapwell が固まらず、終了できる (実機未確認)
- [ ] 応答しない最大化されたウィンドウでホットキーを押しても、ほかのウィンドウのドラッグとホットキー、一時停止、終了が効く (実機未確認)
