# モックアップの CSS を、WinUI・GDI に移すときの規則

`docs/mockups/snapwell.html` が見た目の基準。値をそのまま写すと、ブラウザと実装側の解釈の違いでずれる。ここに、見つかったずれと、その避け方を残す。新しい差が見つかったら足す。

## 基本方針
- **ページや描画の中に、見た目の値を直書きしない**。CSS の意味を再現する部品（タグ、キー表示、スイッチなど）を 1 か所に作り、ページはそれを呼ぶだけにする。値を直す場所を 1 つにして、ずれる余地を減らす
- 値は CSS から 1 つずつ読む。単位は、CSS の px を WinUI の DIP にそのまま写す（拡大率はどちらも OS が掛ける）。オーバーレイ（GDI）は、論理 px × 拡大率の物理ピクセルにする

## 見つかったずれ

| CSS の挙動 | 実装側の挙動 | 避け方 |
|---|---|---|
| `border-radius: 9999px` は、高さの半分で切り詰められ、カプセル型になる | WinUI の `Border` は、半径が高さの半分を超えると縦横比で拡大し、楕円になる | 半径は「実際の高さ ÷ 2」にする。固定の高さ（行高 + 縦 padding）が分かるなら、その半分の値を使う。分からない部品は、`SizeChanged` で `CornerRadius` を更新する |
| SVG は小数座標のまま、アンチエイリアスで描かれる（例: 枠 0.5〜17.5、塗り 1.5〜16.5） | 矩形を整数ピクセルに丸めると、拡大率 1.5 などで端が半ピクセルずれ、隙間が非対称になる | 小数の座標のまま描く。整数の矩形型（`PixelRect`）に、図形の座標を入れない |
| `.switch` は 40×20。つまみは枠の内側 | WinUI の `ToggleSwitch` 標準テンプレートは、最小幅・内側の余白・ラベルの列を持ち、40×20 に収まらない | テンプレートを丸ごと作り直す。`MinWidth`・`MinHeight`・`Padding` を 0 にし、各要素の寸法を CSS と数値で突き合わせる |
| 枠 (`border: 1px`) は、要素の寸法の内側に入る (`box-sizing: border-box`) | WinUI の `BorderThickness` は、内容の外側に足される場合がある | 寸法を測って合わせる。合わなければ、`Width`・`Height` を固定して `BorderThickness` を内側に収める |
| 同じ色の面と枠を並べると、継ぎ目が見えない | アンチエイリアスで、面と枠の境に薄い線が二重に見える | 同じ色の状態では、枠の太さを 0 にする |
| `line-height` は、行の高さを決める | `TextBlock` の高さは、フォントの寸法で決まる | `LineHeight` と `LineStackingStrategy="BlockLineHeight"` を指定する |
| `letter-spacing: 0.05em` | `CharacterSpacing` は 1/1000 em の単位 | 0.05em は 50 |
| `accent-color: var(--ink)` | WinUI の標準の強調色（水色）が残る | ブラシのリソースを、ライト・ダークの両方で上書きする |
| 面の重なり（`.snav` は `--surface-2`、ページは `--surface`） | `NavigationView` の標準の面は、下地より明るい色になる | 標準の背景リソースを、モックアップの面に上書きする |

## 確認
- 見た目は、画面を目で見て確かめるだけにしない。モックアップのブラウザ描画と、実機のスクリーンショットを、同じ大きさで重ねて差を測る
- 画素の期待値（面の色、部品の寸法）は、実機の画素を測って記録する
