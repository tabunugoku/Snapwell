# Snapwell 多言語対応 設計書

対象の言語は、日本語、英語、中国語の簡体字（`zh-Hans`）、中国語の繁体字（`zh-Hant`、台湾の語彙と表記）。
既定は OS の言語に合わせ、4 つのどれでもなければ英語にする。設定画面の「一般」の「言語」で、自動／日本語／English／简体中文／繁體中文 を選べるようにする。
用語と表記は `docs/I18N_GLOSSARY.md`。

この文書のファイル名と行番号は、実装前の 2026-10-22 の main（f65e5bf）のもので、いまはずれている。実装の状況は §9。

---

## 1. 文言の持ち方（実装前の調査の要約）

実装前は、画面の文言が Core・App・Settings（XAML とコード）に日本語で直書きされていた。同じ文言が XAML と Core の両方にあり（例: 「角丸を強制する」）、件数・連結・複数形を含む文が翻訳で崩れやすい箇所だった。これらは今は、キーとプレースホルダー（§7）で持つカタログに移してある。調査時の件数と箇所の一覧は、履歴（2026-10-22 の main、f65e5bf）を見る。

## 2. 仕組みの選択

### 2.1 前提になった事実

1. **App と Settings はどちらも `InvariantGlobalization=true`**（`Snapwell.App.csproj`、`Snapwell.Settings.csproj`）。`CultureInfo.CurrentUICulture` はインバリアントになり、OS の言語は .NET から取れない。`.resx` のサテライト アセンブリは `CultureInfo` で選ぶ仕組みなので、この構成に合わない。`Directory.Build.props` の `SatelliteResourceLanguages=ja;en` も、パッケージのサテライトを絞る設定で、ここでは関係しない。
2. **App（常駐する本体）は Windows App SDK を参照していない**。MRT Core（`ResourceLoader`）は使えない。本体のメモリを小さく保つ方針（DESIGN.md §14）から、文言のためだけに参照を足さない。
3. **Core の表示名は Settings と App の両方で使う**。`HotkeyCatalog` の操作名はホットキーのページ・ランチャー・ウィザードで、角や配置のタグは「アプリのルール」と書き出しの差分で使う。設定画面の XAML にも、Core と同じ文言がある（例: 「角丸を強制する」は `RuleDialog.xaml`、`LookPage.xaml`、`WindowRuleListEditor.cs:120`、`SettingsTransfer.cs:299` の 4 か所）。
4. **Settings の窓の検索がタイトルに依存している**。`SettingsWindowActivator.cs:13, 15` が「Snapwell の設定」「Snapwell の初回セットアップ」で `FindWindowEx` する。タイトルを訳すと、2 つ目の起動が既存の窓を見つけられなくなる。
5. **`LauncherLog.Format` が例外の文言で分岐している**（`LauncherLog.cs:24–40`）。開発者向けのメッセージを訳すと、ログが `[redacted]` になる。

### 2.2 スパイクで確かめたこと（要約。捨てるコードで、リポジトリに入れていない）

main（f65e5bf）の worktree で、Settings に `.resw` + `x:Uid` と `ResourceLoader` を足し、`dotnet publish`（NativeAOT、win-arm64・win-x64。この PC は ARM64 で、x64 はエミュレーション）で確かめた。

- `.resw` の 4 言語の PRI は生成され、`x:Uid` と `ResourceLoader().GetString` は NativeAOT・パッケージ化なしで動く。Windows App SDK 版の `Microsoft.Windows.Globalization.ApplicationLanguages.PrimaryLanguageOverride` は `ja-JP`・`en-US`・`zh-Hans`・`zh-Hant` で効く（`zh-TW`・`zh-CN` は対応する言語に当たる）。上書きは次の起動に残らない。
- OS 版の `Windows.Globalization.ApplicationLanguages.PrimaryLanguageOverride` はパッケージなしで例外になり、`ManifestLanguages` も例外になる。どちらも使わない。
- OS の言語の API はこの PC で食い違った（`GetUserDefaultUILanguage` は ja-JP、`GetUserPreferredUILanguages` は `en-US` が先頭）。表示言語と MRT に合うのは `GetUserDefaultUILanguage` なので、これを使う（§3.2）。

### 2.3 比べた案

| 案 | 内容 | 判断 |
|---|---|---|
| (a) WinUI の `.resw` + `x:Uid`（Settings）と、App・Core 用の別の仕組み | Settings は MRT。App と Core は自前のカタログ | **捨てた**。動くことはスパイクで確かめたが、文言の置き場所が 2 つになる。§2.1 の 3 のとおり、同じ文言が XAML と Core の両方にあり、訳語のずれをテストで防げない。MRT は足りないキーを黙って既定の言語（英語）に落とすので、漏れが見えにくい |
| (b) `.resx` + `ResourceManager` | .NET 標準 | **捨てた**。`InvariantGlobalization` と合わない（§2.1 の 1）。NativeAOT ではサテライトの配置とトリミングに注意が要る。App にも Settings にも同じ問題が残る |
| (c) Core の 1 つのカタログ（埋め込みの JSON）と、XAML 用の添付プロパティ | 4 言語の文言を Core に置き、Settings・App・Core が同じ関数で引く。XAML は `x:Uid` の代わりに自前の添付プロパティでキーを指定する | **推奨** |
| (d) ソースジェネレーターで、キーごとの型付きプロパティを生成 | 綴りの誤りをコンパイルで検出できる | 今は採らない。別のアナライザー プロジェクトが要る。(c) のテスト（§6）で同じ漏れを検出できる。キーが増えて誤りが目立つようなら、フェーズ 4 のあとに検討する |

### 2.4 推奨: Core の 1 つのカタログ

**置き場所と形式**

- `src/Snapwell.Core/Localization/Strings/ja.json`、`en.json`、`zh-Hans.json`、`zh-Hant.json`。
- 平らなオブジェクト（キー → 文言）。`//` のコメントを許し、訳す人への注記（プレースホルダーの意味、文字数の目安）を書く。
- `Snapwell.Core.csproj` で `EmbeddedResource`（`LogicalName="i18n/%(Filename)%(Extension)"`）にする。App と Settings の exe に入り、ファイルの配置は増えない。

**読み込み**

- `Utf8JsonReader`（`JsonCommentHandling.Skip`）で読む。`JsonSerializer` もリフレクションも使わない。`System.Text.Json` はすでに設定ファイルで使っているので、依存は増えない。
- 起動時に、選んだ言語と英語（落とし先）の 2 つだけを読む。
- キーがないとき: 選んだ言語 → 英語 → キーそのもの、の順に落とす。Debug ビルドでは `⟦キー⟧` を返して目立たせる。

**API（Core。名前は案）**

```csharp
public enum UiLanguage { Japanese, English, ChineseSimplified, ChineseTraditional }

public sealed class TextCatalog            // 1 言語分。テストでは言語を指定して作る
{
    public static TextCatalog Load(UiLanguage language);
    public string Get(string key);
    public string Format(string key, params (string Name, object Value)[] args);
    public string Plural(string key, int count, params (string Name, object Value)[] args);
}

public static class UiText                 // プロセスで 1 つの現在の言語
{
    public static TextCatalog Current { get; }   // 既定は日本語（テストを OS の言語に依存させない）
    public static void Use(UiLanguage language); // 参照の差し替え（volatile）。どのスレッドから呼んでもよい
}
```

- 型の名前を `Text` にしない。`TrayMenuRenderer` などに `Text(...)` というメソッドがあり、`Text.Current` がメソッドに結びついてコンパイルできない。別名（`using L = ...`）で逃げると、§6 の参照の網羅のテストがキーを拾えなくなる。呼び出しは必ず `UiText.Current.Get("...")` / `.Format("...")` / `.Plural("...")` の形で書く。
- Core 自身は OS の言語を読まない。`UiText.Current` の既定を日本語にし、既存のテスト（日本語の文字列で比べている 191 件）を変えずに通す。
- 既存の関数（`HotkeyCatalog.GetDisplayName` など）は、引数を変えずに中身を `UiText.Current` に置き換える。言語を変えたテストは `TextCatalog.Load(...)` を直接使う。

**XAML: 添付プロパティ `Loc.Uid`**

- `Snapwell.Settings/Localization/Loc.cs` に `Loc.Uid`（string）の添付プロパティを置く。値が入ったとき、カタログの `<Uid>.<プロパティ>` を探して要素に設定する。
- 対応するプロパティの接尾辞（`x:Uid` の書き方に合わせる）: `Text`、`Content`、`Header`、`PlaceholderText`、`Title`、`PrimaryButtonText`、`SecondaryButtonText`、`CloseButtonText`、`Message`（InfoBar）、`ToolTip`（`ToolTipService.ToolTip`）、`AutomationName`（`AutomationProperties.Name`）。
- 型ごとの割り当ては `switch` で書き、リフレクションを使わない（NativeAOT）。既存の添付プロパティ（`controls:Pill.AutoRadius`、`controls:SpringToggle.Enabled`）が NativeAOT で動いているので、同じ作りでよい。
- 例:

  ```xml
  <TextBlock l:Loc.Uid="General_EnabledTitle" Style="..." />
  <ToggleSwitch l:Loc.Uid="General_EnabledToggle" ... />
  ```

  ```jsonc
  "General_EnabledTitle.Text": "Snapwell を有効にする",
  "General_EnabledToggle.AutomationName": "Snapwell を有効にする",
  ```

- 移行した要素からは、日本語の `Text="..."` を消す（カタログと二重に持たない）。

**WinUI 自身の文言とフォントの選択**

- WinUI の組み込みの文言（テキストボックスの右クリック メニューなど）は MRT が選ぶ。そのため、Settings の起動時に `Microsoft.Windows.Globalization.ApplicationLanguages.PrimaryLanguageOverride` を、決めた言語のタグ（`ja-JP` / `en-US` / `zh-Hans` / `zh-Hant`）に必ず設定する。「自動」のときも、Core で決めた結果を明示的に設定する。MRT に独自の判断をさせず、App と Settings の言語がずれないようにするため。
- ウィンドウのルート要素の `FrameworkElement.Language` にも同じタグを入れる（漢字の字形の選択に効く。§5.3）。

## 3. 言語の決め方

### 3.1 保存場所: 端末状態（`device.json`）

**推奨: `DeviceState` に `Language` を足し、端末状態のスキーマを版 4 に上げる。**

| | `DeviceState`（`%LOCALAPPDATA%\Snapwell\device.json`） | `PortableSettings`（`settings.json`、同期対象） |
|---|---|---|
| DESIGN.md §12.1 の分け方 | 「この PC だけのもの」（標準機能、同期フォルダー）と同じ扱い | ホットキー・分割案などの共有するもの |
| 版を上げたときの影響 | この PC の中だけ | 版 13 にすると、古い Snapwell の PC から見て同期ファイルが「新しい版」になる。同期が見送られ（`SettingsSync.cs:179`）、書き出しも読めなくなる |
| PC ごとに OS の言語が違う場合 | PC ごとに選べる | 一方の PC の選択が、ほかの PC に移る |
| 本体の反映 | 本体はすでに `device.json` を監視している（`AppHost.cs:84` の `OnDeviceChanged` → `ApplyDevice`）。動的に切り替えられる | 本体も監視しているが、同期の取り込みでも変わる |

**形式**

- `"Language": "auto" | "ja" | "en" | "zh-Hans" | "zh-Hant"`（文字列）。
- 列挙型にしない。`SettingsJsonContext` は `UseStringEnumConverter = true` なので、未知の列挙値の文字列で `JsonException` になり、端末状態全体が壊れたと扱われる。文字列なら、未知の値を `auto` に正規化できる。

**移行**

- `DeviceState.CurrentSchemaVersion` を 4 にする。`DeviceState.Migrate` で、版 3 以下は `Language = "auto"`。
- 版 4 のファイルを古い Snapwell が読むと、既存の方針どおり読み取り専用で保護される（有効・無効の切り替えなどが保存できなくなる）。新しい版を入れて古い版に戻す場合だけに起きる。

### 3.2 OS の言語の取得

- Platform に `OsLanguageSource.GetDisplayLanguageTag()` を置く。`GetUserDefaultUILanguage` で表示言語の LANGID を取り、`LCIDToLocaleName` でタグ（例 `ja-JP`、`zh-TW`）にする。どちらも CsWin32 で生成する（文書化された公開 API）。
- `GetUserPreferredUILanguages` は使わない。この PC で表示言語と違う値を返したため（§2.2）。
- 呼ぶのは起動時だけ。表示言語の変更は、サインアウトするまで反映されないため。

### 3.3 判定（Core の純粋関数）

`UiLanguageResolver.Resolve(string preference, string? osTag) → UiLanguage`

- `preference` が `ja` / `en` / `zh-Hans` / `zh-Hant` なら、それを返す（OS は見ない）。
- `auto` か未知の値なら、`osTag` から決める。
- `osTag` は大文字小文字を区別せず、`_` を `-` として扱う。

| OS のタグ | 結果 | 理由 |
|---|---|---|
| `ja`、`ja-JP`、`ja-*` | 日本語 | |
| `en`、`en-US`、`en-GB`、`en-*` | 英語 | |
| `zh-Hans`、`zh-Hans-*`（例 `zh-Hans-CN`、`zh-Hans-HK`） | 簡体字 | 文字体系の指定を地域より優先する |
| `zh-Hant`、`zh-Hant-*`（例 `zh-Hant-TW`、`zh-Hant-HK`） | 繁体字 | 同上 |
| `zh-CN`、`zh-SG` | 簡体字 | |
| `zh-TW`、`zh-HK`、`zh-MO` | 繁体字 | 香港・マカオも繁体字。語彙は台湾のものになる（要判断。§8） |
| `zh`（地域も文字体系もなし） | 簡体字 | Windows の表示言語では通常出ない。話者の多いほうに寄せる |
| `zh-` で始まる上記以外（例 `zh-MY`） | 簡体字 | マレーシアは簡体字 |
| `zh-Hant-*` 以外の文字体系つき（例 `zh-Latn`） | 英語 | 想定外の形式は英語 |
| 空、`null`、解析できない値 | 英語 | |
| 上記以外（`fr-FR`、`ko-KR` など） | 英語 | |

### 3.4 反映のしかた

- **本体（App）**: 起動時に `Resolve` して `UiText.Use` する。`device.json` の変更（`ApplyDevice`）で `Language` が変わったら、もう一度 `Resolve` して `UiText.Use` し、トレイのホバー文言を更新する。トレイメニューとランチャーは、開くたびに文言を作り直すので、次に開いたときから新しい言語になる。再起動は要らない。
- **本体の状態の文言**: いま `AppHost` は、状態を日本語の文字列で `_status` などに持っている。フェーズ 4 で、文字列ではなくキー（と引数）で持ち、表示のたびに文言にする。フェーズ 1 から 3 の間は、言語を変えても、すでに出ている状態の文言は前の言語のまま残る（次に状態が変わると新しい言語になる）。
- **設定画面（Settings）**: 起動時に、`InitializeComponent` の前に `Resolve` → `UiText.Use` → `PrimaryLanguageOverride` → フォントの差し替え（§5.3）。「言語」を変えたら、有効・無効のトグル（`GeneralPage.xaml.cs`）と同じく、保存ボタンを待たずに `device.json` へ保存する（本体はすぐ切り替わる）。設定画面の表示は、開き直したときに切り替える。そのことを InfoBar で知らせる。開いたまま作り直す案は §8 の要判断。
- **ウィザード**: Settings と同じ起動経路（`App.xaml.cs` の `OnLaunched` で `SetupWindow`）なので、同じ処理で言語が決まる。
- **窓の検索**: `SettingsWindowActivator` は、4 言語の窓のタイトルを順に探す（タイトルは訳すが、検索の文言の一覧はカタログから全言語分を取る）。

## 4. 訳すもの・訳さないものの境界

| 対象 | 扱い | 理由・注意 |
|---|---|---|
| XAML の文言、`AutomationProperties.Name`、ツールチップ、InfoBar、ダイアログ | 訳す | |
| ウィンドウのタイトル（「Snapwell の設定」） | 訳す | §3.4 の窓の検索を合わせて直す |
| トレイのメニュー・ホバー・状態タグ、ランチャーの文字、MessageBox | 訳す | |
| `AppHost`・`SettingsSyncService` の状態の文言 | 訳す | トレイに出る。ログではない（§1.3） |
| Core の検証メッセージ・状態・表示名（敬体の文） | 訳す | |
| ファイル選択のフィルター名（「JSON ファイル」） | 訳す | |
| 例外のメッセージ（常体「〜できない。」） | **訳さない**（日本語のまま） | 開発者向け。`LauncherLog.Format` が文言で分岐している（§2.1 の 5）。画面には出さない |
| ログ（`app.log`、`launcher.log`、`CornerStyler` のログ） | 訳さない | 同上 |
| コードのコメント、`docs/` | 訳さない | 開発方針（コメントは日本語） |
| 設定ファイルのキー（`SchemaVersion`、`LauncherPresets` の ID など）、列挙の値 | 訳さない | 保存形式 |
| ランチャーのプリセット ID、`WindowCommand` の名前 | 訳さない | 保存形式 |
| 操作感の識別子（Standard・Crisp・Smooth・Bouncy） | 識別子は訳さず、画面の表示名は言語ごとに訳す | 識別子は `FeelPreset.ByName` の照合に使う。旧識別子 Airy・Snappy・Heavy は別名として読み、保存は新識別子に揃える。表示名は `Feel_PresetName_Standard.Text` などを使う |
| キーの表記（Ctrl・Alt・Shift・Win・Esc・Enter・Space・PageUp・矢印 ←→↑↓） | 訳さない | `HotkeyCatalog.FormatChordParts`。キーボードの刻印に合わせる |
| 単位「px」「Hz」、記号「×」「m」「f」「ζ」 | 訳さない | |
| 言語名（日本語・English・简体中文・繁體中文） | 訳さない（各言語での自称） | どの言語の画面でも、自分の言語を見つけられるように |
| ユーザーのデータ（ウィンドウのタイトル、プロセス名、フォルダーのパス） | 訳さない | |
| OS の画面の名前を引用する文言（「ウィンドウのスナップ」「アニメーション効果」「タスク スケジューラ」など） | 各言語の **Windows の表記に合わせる** | 自由に訳すと、利用者が OS の設定で見つけられない。用語集で「要確認」とし、各言語の Windows で確かめる |

例外の文言の境界: 例外を `catch` して画面に出している箇所は、例外の `Message` を出さず、呼び出し側で用意したキーの文言を出す。いまの `Settings` の InfoBar は、すべて呼び出し側の固定の文言を使っている。変数を入れている箇所も、たどると固定の文言だった: `GeneralPage.xaml.cs:143`（`:73, 79, 117, 122` の固定文）、`OsPage.xaml.cs:249`（`:34, 40, 121–224` の固定文）、`MainWindow.xaml.cs:157`（`SettingsSession.TrySave` の固定文、`SettingsSession.cs:90–123`）、`SetupWindow.xaml.cs:100`（`SetupWizard.TryNext` の固定文、`SetupWizard.cs:84–85`）、`BackupPage.Transfers.cs:114`（`:36–109` の固定文と `SettingsTransfer` の読み込みの失敗理由 `:141–165`）、`BackupPage.Sync.cs` の `ShowNotice`（固定文、`SettingsSync.ValidateFolder`、`SettingsSyncResult.ToDisplayText`）。`WindowRuleListEditor.Add` の例外（`WindowRuleListEditor.cs:13`、敬体）は画面に出るかを確かめていない（未確認）。出るならキーの文言に替える。

## 5. レイアウトとフォント

### 5.1 長さの見立て

- 英語は文字数が増えるが、字幅は日本語の約半分。画面の幅では、日本語の 1.0〜1.4 倍になる見込み（推測。フェーズごとの実機確認で確かめる）。中国語は日本語と同じか短い。
- 崩れやすいのは英語。

### 5.2 崩れそうな箇所と対策

| 箇所 | いまの寸法 | 懸念 | 対策 |
|---|---|---|---|
| ホットキーのページ（最小幅 900） | 操作名 3*、キー 4*、状態 120、操作 72（`HotkeysPage.xaml.cs:143–146`） | 日本語でも、最小幅で長い操作名 4 つが語の途中で折り返している（`MANUAL_TEST.md:236`）。英語の操作名は長い。状態の「In use by another app」が 120 に収まらない | 英語の操作名を短く作る（用語集の簡潔な形）。状態の列は折り返しを許すか、短い語（「In use」）にする（要判断） |
| ウィザード（820 × 720 で固定。`SetupWindow.xaml.cs` の `WizardWidth`・`WizardHeight`） | 固定 | 英語の説明文と、キーの図の行（「+ arrow keys for halves」）が溢れる | 文言を短く。キーの図と文の交互をテンプレートにして、折り返しを許す（フェーズ 3） |

### 5.3 フォント（字形の誤りは見た目でなく正しさの問題）

- 漢字は日本語と中国語で同じ文字コードを使う（Han unification）。いまは日本語の書体に寄せているため、中国語の画面で日本語の字形になる。
  - 設定画面: `SnapwellUiFontFamily` と `ContentControlThemeFontFamily` が `Segoe UI Variable Text, Segoe UI Variable, Yu Gothic UI`（`App.xaml:461–462`）。
  - オーバーレイとトレイ: `GdiOverlayText.Font` が、ASCII 以外の文字（`×` と `·` を除く）を「Yu Gothic UI」で描く（`GdiOverlayText.cs:45, 299`）。
- 言語ごとの書体:

  | 言語 | UI の書体の並び | GDI（本体）の CJK の書体 |
  |---|---|---|
  | 日本語 | `Segoe UI Variable Text, Segoe UI Variable, Yu Gothic UI` | Yu Gothic UI |
  | 英語 | 同上（ウィンドウのタイトルなどに日本語が入るため） | Yu Gothic UI |
  | 簡体字 | `Segoe UI Variable Text, Segoe UI Variable, Microsoft YaHei UI` | Microsoft YaHei UI |
  | 繁体字 | `Segoe UI Variable Text, Segoe UI Variable, Microsoft JhengHei UI` | Microsoft JhengHei UI |

- 設定画面: 起動時に、`Application.Current.Resources` の 2 つの `FontFamily` を言語に合わせて差し替え、ルートの `Language` にタグを入れる。`StaticResource` は要素の読み込み時に引くので、窓を作る前に差し替える。この順で効くかは実機未確認（フェーズ 1 で確かめる）。
- 本体: `GdiOverlayText` の `japanese` の判断を「CJK」と読み替え、書体の名前を `UiText.Current` の言語から選ぶ。
- ページの題の明朝（`SnapwellDisplayFontFamily` = Yu Mincho、`App.xaml:463`）は中国語では UI の書体の Medium にする（§8 の 4）。

## 6. テストの方針

すべて Core のテスト（`tests/Snapwell.Core.Tests`）で行う。OS の言語に依存させない。

1. **言語の判定**: §3.3 の表の各行を `[Theory]` で確かめる。`preference` が明示のときは `osTag` を見ないこと。
2. **端末状態の移行**: 版 3 のファイルが `Language = "auto"` で読めること。未知の値が `auto` になること。版 5 のファイルが読み取り専用になること。
3. **キーの網羅**: 4 言語の JSON のキーの集合が完全に一致すること。値が空でないこと。
4. **プレースホルダーの一致**: 各キーで、`{名前}` の集合が 4 言語で一致すること。`{{` / `}}` の扱い。
5. **複数形の対**: `.One` で終わるキーには `.Other` があること（逆も）。
6. **参照の網羅**: リポジトリの `src/**/*.cs` と `src/**/*.xaml` を読み、次がすべて `ja.json` にあること。`UiText.Current.Get("...")` と `.Format("...")` のキーはそのまま、`.Plural("...")` のキーは `<キー>.One` と `<キー>.Other` の両方、`Loc.Uid="..."` は `<Uid>.` で始まるキーが 1 つ以上。テストはリポジトリのルート（`Snapwell.sln` のあるフォルダー）を、テストの出力フォルダーから上へたどって探す。
7. **表示名の網羅**: `WindowCommand`、`LauncherPreset.All`、`PlacementRule`、`CornerRule`、`SettingsSyncKind` の全値に、4 言語のキーがあること。
8. **言語の固定**: 既存のテストは `UiText.Current` の既定（日本語）のまま通る。英語と中国語の表示は `TextCatalog.Load(UiLanguage.English)` を使うテストで確かめる。テストの中で `UiText.Use` を呼ぶ場合は、`IDisposable` で元に戻し、並列に走るテストと共有しない（`[Collection]` で直列にする）。

ビルド時の検出は追加しない。push の前に `dotnet test` を通す運用（開発方針）で十分なため。

## 7. キー・プレースホルダー・文体

### 7.1 キーの名前

- XAML の Uid: `<ページ>_<要素>`（PascalCase、`_` でつなぐ）。プロパティはカタログのキーの末尾に `.<プロパティ>` で付ける。例: `General_EnabledTitle.Text`、`General_EnabledToggle.AutomationName`、`Nav_General.Content`。Uid に `.` を使わない（プロパティの区切りと紛れるため）。
- コードのキー: `<領域>.<項目>[.<細目>]`。例: `Tray.Arrange`、`Tray.Status.Paused`、`Command.LeftHalf`、`Command.Resize.Center.GrowRight.One`、`Sync.Status.Pushed`、`Rule.Error.NoCondition`、`Language.Auto`。
- 列挙の値から作るキーは、列挙の名前をそのまま使う（`Command.{WindowCommand}`）。NativeAOT でも `Enum.ToString()` は使える（既存の `TrayIconPolicy.ResourceName` が使っている）。
- 共通の語（保存、取り消す、既定に戻す、未設定など）は `Common.*` に置き、ページごとに同じ文言を作らない。

### 7.2 プレースホルダー

- 名前つき: `{count}`、`{step}`、`{name}`、`{chord}`。位置の番号（`{0}`）は使わない（訳す人が意味を取れ、語順を変えやすいため）。
- 数値は呼び出し側で文字列にしない。`Format` が `CultureInfo.InvariantCulture` で書式にする。
- 複数形: 数を含む文は `.One` と `.Other` の 2 つのキーにし、4 言語ともに両方を書く（日本語と中国語は同じ文言でよい）。`Plural` は英語のときだけ `count == 1` で `.One` を選ぶ。
- 文の断片をつなげない。キーの図をはさむ文は、`{keys}` のようなプレースホルダーを含む 1 つのテンプレートにし、描画側でテンプレートを文字とキーの図に分ける（フェーズ 3・4）。
- 日時は、言語ごとの書式文字列をカタログに持つ（`Common.DateTimeFormat`）。

### 7.3 文体

用語集（`docs/I18N_GLOSSARY.md`）の §1 に従う。

## 8. 決定事項（2026-10-22）

すべて推奨どおり。ただし翻訳の確認だけは、母語話者の確認を行わず、実装役が用語集に沿って書き、Claude が確認する形で進めた（公開後も母語話者の確認はまだ。不自然な点は Issues で受ける）。

1. 仕組みは、Core の 1 つのカタログ（埋め込みの JSON）と添付プロパティ `Loc.Uid`。
2. 設定画面の言語は、開き直したときに切り替える（InfoBar で知らせる）。
3. 保存場所は端末状態（`device.json`）。
4. ページの題の明朝は、中国語では UI の書体（YaHei／JhengHei）の Medium。
5. `zh-HK`・`zh-MO` は繁体字（台湾の語彙）にする。
6. OS の表示言語は `GetUserDefaultUILanguage` で取る。表示言語の一覧の 2 番目以降は見ない。
7. 用語の「要判断」は `docs/I18N_GLOSSARY.md` で決めた。
8. 同意の MessageBox は MessageBox のまま、タイトルと本文だけ翻訳する。「はい／いいえ」は OS の言語で出て混在する（`TaskDialogIndirect` への移行は課題）。
9. ホットキーの状態の列は短い語にする（英語は「In use」）。
10. 「言語」のドロップダウンの幅は 160 → 200。
